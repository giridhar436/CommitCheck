Reference Sheet 02

Next.js App Router Architecture

File conventions, request lifecycles, and component boundaries.

1. Special File Conventions in src/app/

File Name Role Execution Target
page.tsx Public UI view for this route folder Server by default
layout.tsx Persistent UI wrapper (navbars, headers) Server by default
route.ts Backend HTTP endpoint (GET, POST, etc.) Server only (never renders HTML)
loading.tsx Automatic streaming loading fallback Client & Server

2. Route Handler Anatomy (route.ts)

Export functions named after standard HTTP methods:

import { NextRequest, NextResponse } from "next/server";

// Handles GET /api/example
export async function GET(request: NextRequest) {
  const searchParam = request.nextUrl.searchParams.get("query");
  return NextResponse.json({ success: true, param: searchParam });
}

// Handles POST /api/example
export async function POST(request: NextRequest) {
  const body = await request.json();
  return NextResponse.json({ received: body }, { status: 201 });
}

3. Server Components vs Client Components

Feature Server Component (Default) Client Component ("use client")
Direct Database Access Yes (Prisma, secrets, DB) No (must call an API)
Browser Interactivity No (no onClick, useState) Yes (state, effects, events)
Bundle Size Zero JS sent to browser Sends JavaScript bundle
