Reference Sheet 01

TypeScript Foundations for JavaScript Developers

Quick-reference syntax and mental models for navigating typed codebases.

1. Primitive Type Annotations

In plain JavaScript, variables hold values without strict constraints. TypeScript adds explicit contracts:

// Syntax: let variableName: type = value;
let repoName: string = "CommitCheck";
let taskCount: number = 8;
let isVerified: boolean = false;
let taskIds: string[] = ["VAR-6", "VAR-7", "VAR-8"];

2. Interface vs Object Literal

Interfaces define the shape of domain objects before they are passed to APIs or stored in databases:

// Defining the contract
interface LinearTask {
  id: string;
  title: string;
  estimate: number;
  isCompleted?: boolean; // '?' marks an optional field
}

// Enforcing the contract
const currentTask: LinearTask = {
  id: "VAR-6",
  title: "Foundation Setup & Role-Enforced Dual OAuth",
  estimate: 3
};

3. Union Types (Restricting Values)

Instead of arbitrary strings, restrict values to specific business states:

// Role enforcement in CommitCheck
type UserRole = "FREELANCER" | "CLIENT";

// Audit discrepancy severity
type DiscrepancyLevel = "LOW" | "MEDIUM" | "HIGH" | "GHOST_COMPLETION";

4. JS vs TS Mental Model Summary

Concept Plain JavaScript TypeScript
Type Checking Runtime (crashes in production) Compile-time (caught in editor)
Object Shapes Assumed implicitly Defined via interface
Output Executed directly by Node/Browser Compiled away to clean JavaScript
