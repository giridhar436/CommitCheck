Lesson 0002

Next.js App Router: Full-Stack Routing & API Endpoints

Demystifying how folders, page.tsx, and route.ts power modern web architectures.

Mission Connection: In traditional JavaScript, building a SaaS required running two separate projects: an Express.js backend server on port 5000 and a React frontend on port 3000. Next.js unifies both in a single repository. Understanding this file-system routing allows you to build APIs, auth endpoints, and client dashboards seamlessly.

1. The File-System Routing Paradigm

In Next.js, the folder hierarchy inside src/app/ directly defines the URLs of your website and APIs:

src/app/
├── page.tsx                    -> https://your-saas.com/ (Homepage UI)
├── freelancer/
│   └── page.tsx                -> https://your-saas.com/freelancer (Dashboard UI)
└── api/
    └── auth/
        └── google/
            └── route.ts        -> https://your-saas.com/api/auth/google (Backend API)

Notice the critical distinction:

  • page.tsx exports a React UI component that renders HTML/CSS onto the user's screen.
  • route.ts is a pure backend endpoint. It never renders HTML. Instead, it processes HTTP requests, reads cookies, contacts external APIs (like Google or Stripe), and returns JSON or redirects.

2. Deconstructing src/app/api/auth/google/route.ts

You have this file open in your editor right now. Let's trace line-by-line how Next.js processes incoming requests:

import { NextRequest, NextResponse } from "next/server";

export async function GET(request: NextRequest) {
  // 1. Next.js automatically passes the incoming HTTP request
  const searchParams = request.nextUrl.searchParams;
  const code = searchParams.get("code");

  // 2. Logic: If no OAuth code exists, redirect the browser to Google
  if (!code) {
    const googleAuthUrl = `https://accounts.google.com/o/oauth2/v2/auth?...`;
    return NextResponse.redirect(googleAuthUrl);
  }

  // 3. If Google sent back a code, exchange it for user profile info
  const result = await handleOAuthCallback(...);

  // 4. Set a secure, encrypted cookie and send the user to their dashboard
  const response = NextResponse.redirect(new URL(result.redirectUrl, request.url));
  response.cookies.set({
    name: "commitcheck_session",
    value: result.sessionToken,
    httpOnly: true // Browser JavaScript cannot tamper with this
  });

  return response;
}

Why Named Exports? (GET, POST)

In plain JavaScript with Express, you wrote app.get("/path", (req, res) => ...). In Next.js, you simply export an asynchronous function named after the HTTP verb: GET, POST, PUT, or DELETE. Next.js automatically wires it to the URL matching the folder path.

Concept Check 1: Why is a file named route.ts in src/app/api/auth/google instead of page.tsx?
It runs exclusively inside the web browser.
It returns HTTP responses rather than HTML.
It compiles static CSS styles for production.
It encrypts stored passwords inside local storage.
Concept Check 2: What happens when you export an async function named GET from a route.ts file?
It automatically creates a database table.
It displays a visible loading spinner.
It installs third party package dependencies.
It handles incoming HTTP GET requests.
